Contribute

Sill is free and open source, made by one person with help from the people on this page. There are four ways to help: a tip, code, a report or an idea.

Sponsor Sill

Sill has no ads, no tracking and no subscription. If it is useful to you, a tip through GitHub Sponsors helps pay for the Apple developer account, the domain and the time that goes into each release. Once or monthly, from $1.

Sponsor on GitHub

A tip unlocks nothing: every feature is free, for everyone. Helping costs nothing too: rate the app on the App Store, star the repository, or tell someone who would use it.

Contributing code

Pull requests are welcome. What makes one easy to merge:

  1. Open an issue first for anything larger than a small fix. Say what you want to change and why. The design gets settled there before the code does, and nobody builds the same thing twice.
  2. Keep to Sill’s rules. Swift and Apple’s frameworks only, with no third-party dependencies. Nothing that needs a server or costs money to run. Latency before picture quality: a frame is dropped before it is queued. A native feel, in iOS and macOS conventions. Older versions keep working: the connection’s format only grows, so a new message or field is optional and a number is never reused.
  3. Build from source. The README says how in a few lines, and DEVELOPMENT.md has the rest: the test hosts, the layout harness and the checks.
  4. Run the checks before you open the pull request: Tests/checks/run-all.sh runs the same pure checks as CI, in about five minutes, with no device. A change to a checked file updates its check in the same commit.
  5. Say what you tried: which Mac and which iPhone or iPad, their system versions, and what you saw. Most of Sill can only be tested with a device, so this is what the review stands on.
  6. One change per pull request, with the words and docs it touches: anything people read in the app follows its voice, plain and short, and the README or the support page say what changed.

Contributions are accepted under the project’s license, the Apache License 2.0; there is no agreement to sign. Please report a security problem privately, as SECURITY.md says, never in a public issue.

Reporting a problem or an idea

Open an issue on GitHub: there is a form for a bug report, one for an idea and one for a question. For a bug, say which Mac and which iPhone or iPad you use, their system versions and what happened. A log helps too: on your Mac, choose Show Log… in the Sill menu. It lists window names, device names and network addresses, never what you copy, so read it before you attach it. Look through the open issues first: your idea may be there already, and a thumbs-up on it counts.

For anything you would rather not post, email support@getsill.app.
